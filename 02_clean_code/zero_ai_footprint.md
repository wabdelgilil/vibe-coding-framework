# Zero AI Footprint

> **Pillar:** [02_clean_code](README.md) | **Hub:** [INDEX.md](../INDEX.md)

## Objective & Scope
Ensure every deliverable—source code, comments, Git history, manifests, documentation, UI copy, and generated office/PDF files—reads as the work of a seasoned human engineer with zero telltale AI artifacts.

## Mandatory Standards
1. **Clean Comments Only:** Comments MUST explain *why* (business rules, domain invariants, non-obvious constraints, mathematical models)—never narrate *what* the syntax obviously does.
2. **Authentic Git History:** Use standard Conventional Commits (`feat:`, `fix:`, `refactor:`, `docs:`, `test:`, `perf:`) written concisely in human engineering voice. Never attach AI co-author trailers or synthetic commit summaries.
3. **Professional Manifests & Document Metadata:** Package manifests (`package.json`, `pyproject.toml`, etc.) and generated documents (`.pdf`, `.docx`, `.xlsx`, `.pptx`) MUST declare real project/organization metadata and strip default library/generator watermarks.
4. **Domain-Authentic Copy & Fixtures:** UI text, error messages, and documentation MUST use direct, concise, professional language free of repetitive AI phrasing or placeholder clichés (`Lorem ipsum`, `Acme Corp`, `John Doe`) in production paths.

## Prohibited Anti-Patterns
- Including automation headers (`# Generated by AI`, `// Created with ...`, `Co-Authored-By: ...`).
- Writing superficial narration comments (`// Initialize variable`, `// Loop through users`, `// Return response`).
- Overusing decorative emojis or flowery hype language in technical code, logs, or formal docs.
- Leaving generator defaults (e.g., `openpyxl`, `python-docx`, template author tags) inside exported deliverables.

## Verification & Audit Checklist
- [ ] Zero AI signatures, co-author tags, or generator watermarks in code, commits, or metadata.
- [ ] Every comment adds domain or architectural value rather than restating code syntax.
- [ ] Documentation and UI copy use direct, authentic, non-boilerplate language.
